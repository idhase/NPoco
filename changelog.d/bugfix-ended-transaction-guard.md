## [2026-11-17 09:45]
- Version 1.1.0. A database whose transaction has ended under it no longer commits anything on its own. SQL Server rolls a transaction back by itself after a deadlock, an error under XACT_ABORT or an error in a trigger. SqlClient then clears the transaction's `Connection`, and a command given that transaction ran with no transaction at all, so code that caught the `SqlException` and carried on committed its later writes while the rest of the work was rolled back. And `CompleteTransaction` skipped the commit silently, so the caller thought the work was committed.
- Every command NPoco runs (sync and async `Execute`, queries, `Insert`, `Update`, `Delete`, stored procedures) now throws an `InvalidOperationException` before it runs when the transaction has ended. A command from the public `CreateCommand` that the caller executes itself isn't covered. `CompleteTransaction`/`CompleteTransactionAsync` forget the transaction, fire the abort interceptors instead of the complete ones, and throw an `InvalidOperationException`; they don't close and reopen the connection, so a connection passed in by the caller keeps its session, and the database can begin a new transaction afterwards. Before, they skipped the commit silently and fired the complete interceptors. `AbortTransaction` stays silent. `InsertBulk` needed no change: `SqlBulkCopy` already refuses an ended transaction.
- A transaction committed elsewhere has no `Connection` either. Code that hands a database an external transaction with `SetTransaction` and keeps using the database after the owner committed must call `SetTransaction(null)` first; `CompleteTransaction` on such a database now throws instead of doing nothing. Idha.Rebus.NPoco does this from the version that requires Idha.NPoco 1.1.0, so bump the two together: with an older Idha.Rebus.NPoco, `OnTransactionCommit` callbacks that write through the handler's database throw.
- Upstream `Database.cs` gains 7 lines (two calls); the checks live in the new `DatabaseEndedTransaction.cs`. NOTICE updated.
